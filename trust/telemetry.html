Telemetry Data Collection and Usage Policy

Last updated: 26 July 2026

This policy governs how Scott Labz handles telemetry data - defined as information regarding how software, systems, or data workflows are used or performing. Telemetry data is often gathered through built-in diagnostic or "phone home" mechanisms where end users or administrators opt-in to share performance telemetry.

1. Core Considerations & Principles

For our purposes, “Telemetry Data” does not include aggregate statistics collected outside of the software (such as total package download counts). When managing or deploying telemetry across Scott Labz systems and client architectures, we evaluate four key criteria:

  • Individual Data Privacy: Ensuring data cannot track or uniquely identify individual users, and avoiding unauthorized collection of personal information.
  • Data Confidentiality: Preventing business-sensitive or proprietary information from being inadvertently exposed or transmitted.
  • Awareness & Consent: Guaranteeing that users and system administrators are fully aware of telemetry collection prior to activation, utilizing explicit opt-in frameworks.
  • Security of Mechanisms: Ensuring diagnostic or telemetry transmission channels do not introduce security vulnerabilities or unintended code execution paths.

2. Default Stance & Review Standards

By default, software and analytics pipelines developed or distributed by Scott Labz do not collect telemetry data from users.

If a project or architecture requires telemetry collection, it must undergo a rigorous internal review addressing:

  • The exact parameters and data points proposed for collection.
  • Absolute anonymization, confirming data contains no personal, confidential, or sensitive enterprise attributes.
  • Transparent user notification and clear, upfront consent workflows.
  • Secure storage, access limitation, and handling protocols for any gathered metrics.

3. Compliance & Documentation

Any approved telemetry collection must be fully documented in public system notes, accessible to authorized project participants, and strictly compliant with the Scott Labz Privacy Policy. This policy applies strictly to default software configurations and does not govern third-party modifications or independent user deployments.
